Layout applies to every user on this account Save Column Layout
  1. Nothing on this screen writes on change. Every control edits a draft the Save bar commits, because a toggle that takes effect the instant it moves gives an operator no way to back out of a half-finished thought — and here a half-finished thought stops a client's feed.
  2. The audit found four labelling strategies in the app: sentence case, Title Case, ALL CAPS, and placeholder-as-label, with required marked by an asterisk about half the time. A settings screen is mostly labels, so this is where the inconsistency read as neglect. One rule: caps for the section band, sentence case for the field, one asterisk, always.
  3. Credentials and endpoints are the dangerous part of this screen — changing one silently stops ingestion for a single tenant, and nobody notices until a recruiter asks why a facility went quiet. So each card carries the consequence and a named owner, and only these changes ask again on save. The rule the case study keeps returning to is that the correct path has to be the easier one.
  4. Grouped by the job someone arrived to do, not by the shape of the database. Nobody opens settings wanting the integrations table; they open it because a sync failed or a client asked for a field renamed. The public-exposure controls sit together for the same reason — that is the block you want to be deliberate about, so it gets its own walls.
  5. Toggles, fields and checkboxes come from the system rather than being rebuilt per view. The audit counted ten form element styles and five different form-rendering patterns coexisting, which is affordable in one screen and not affordable across forty.
  6. This is where multi-tenancy stops being architecture and becomes something an account manager can touch. The grid on Job Listings is drawn from whichever of 54 normalised fields this client selected, in the order they put them, so a per-diem agency and a travel agency each see their own vocabulary instead of a lowest-common-denominator table. Selected order is table order, so dragging is the only sane control.
