  1. Profession and specialty here are the same mapped vocabulary the job listings grid uses, not free text copied off a CV. Matching a nurse to a requisition is only possible because both sides were normalised upstream, which is why the mapping work sits before every screen in this product rather than beside them.
  2. Credential expiry is a state on the record, not a field inside a tab. A lapsed licence makes someone unplaceable, so it belongs in the roster column an operator already scans — the alternative is discovering it when a submission is rejected, which costs the placement and the relationship.
  3. Tabs split the record by how often each part changes: credentials monthly, availability weekly, match history continuously. One long scroll would make a recruiter re-read the parts that never move to reach the part that always does.
  4. A profile is assembled from the ATS, from uploaded documents and from VMSpark's own matching, so every value carries where it came from. An operator on the phone needs to know whether a licence expiry is what the ATS believes or what the candidate actually sent, because those disagree often enough to matter.
  5. Match history lives on the person rather than only on the requisition. Recruiters ask "where have we put her forward already" far more often than they ask the reverse, and without it the same candidate gets submitted twice to the same facility.
  6. The ATS stays the system of record and this view is read-mostly. Making VMSpark a second place to edit the same person would guarantee two versions of a phone number, so writes are pushed back rather than kept — the exceptions are the fields the ATS has no column for, like preferred states.
