The Design System

One button, one field, one table, one set of tokens — shipped as a page inside the app so the system is the shortest path, not a document beside it.

Colour carries three meanings and no others: accent is the primary action and the current thing, ok is a terminal success, warn is a failure or an impersonated session. Everything else is neutral. A raw hex in a view is a lint failure, so background: #f7f8fa no longer compiles — --surface-alt is the only way to say it.

  • Header band on --surface-alt, 10px uppercase. One header treatment, not four.
  • Sorted column carries the caret and the accent; the sort persists per user.
  • Filter row is always visible, never behind a toggle. No striping — the hairline does the work and striping fights the row states.
  • Selected row: accent-soft fill. The one blue on the row.
  • Failed row: warn tint, the offending cell in warn ink. It stays in the list.

One density: 30px rows, 10.5px cells. Chosen for scanning three thousand rows, not for looking roomy on a settings page.

Contrast · checked at the token
Every ink and accent pair is measured against --surface and --surface-alt before it enters the palette. ink 14.7:1 muted 4.8:1 accent 4.9:1
  1. The token layer was not missing. _color_tokens.scss already defined semantic colour, and roughly forty views ignored it in favour of inline styles and hex literals. So the fix was not another abstraction — it was making the token the shortest path to the result, and making the raw hex fail the build. A system nobody reaches for is indistinguishable from no system.
  2. Eight button styles were not eight decisions; they were the same decision made eight times by people who could not find the previous one. Collapsing to one component with variants means the question a screen author asks changes from “what should this button look like” to “is this the primary action here” — which is a question they are actually qualified to answer.
  3. Five ways to render a form and ten ways to style an input all resolved to the same concept: pick one from a list. The primitives take the choice away, and the focus ring in particular is a single token — the moment focus styling is per-view, it gets deleted by whoever finds it ugly, and keyboard users lose the app.
  4. The expensive half of the labelling work was not the CSS, it was agreeing that Bill Rate, Rate and Pay Rate were one field. Casing is a rule you can write down in an afternoon; reconciling the vocabulary meant sitting with operators and finding out which name they actually used out loud, then changing every screen to match it.
  5. Density was the one table decision worth arguing about. Six conventions existed because each screen picked a density in isolation, so the system picks once and picks for the hardest case — an operator scanning three thousand requisitions, not an admin editing six rows. Row state stays a tint rather than an icon column, because tinting survives being read at speed.
  6. Accessibility is in the primitives rather than in a checklist at the end. Contrast is proven when a token enters the palette, focus and keyboard behaviour ship with the component, and the ARIA lives in the shared partial. That way the default path is the accessible one and a screen author has to work at it to ship something broken — the retrofit alternative means auditing every new view forever.
