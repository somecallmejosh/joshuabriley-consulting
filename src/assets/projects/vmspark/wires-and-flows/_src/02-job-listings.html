  1. Every screen is scoped to one client, and an internal operator can be looking at any of them. The workspace name sits in the chrome rather than in a settings page, and the amber return-to-owner control stays visible the whole time someone is impersonating — the expensive mistake here is reprocessing three thousand listings against the wrong tenant.
  2. A saved page captures filters, visible columns and sort as one shareable view. Triage questions recur weekly (“Mercy, telemetry, failed”), so the unit worth saving is the whole query, not a bookmark of the URL.
  3. Reprocess is queued, never synchronous. One mapping fix can touch thousands of listings, so the button hands off to a job and the progress bar reports depth — a button that blocks for four minutes gets clicked twice.
  4. The tab counts double as queue depth per processing state, so the size of the problem is legible before anyone clicks into it. Failed is a count, not a badge you discover.
  5. A filter input under every column keeps query building inline rather than behind a modal. Operators arrive knowing one fact — a facility, a REQ number — and the fastest path is typing it where they are already looking.
  6. Failed rows stay in the main list, tinted rather than exiled to a separate screen. Triage is then one pass instead of two, and the failure is visible next to the healthy rows it is supposed to look like — here, a facility string the mapper could not resolve.
  7. Page size, sort direction and column widths persist per user, so a triage layout survives a reload and a shift change. The column set itself is account-configurable from 50+ mapped fields, so each client sees its own vocabulary rather than a lowest-common-denominator grid.
