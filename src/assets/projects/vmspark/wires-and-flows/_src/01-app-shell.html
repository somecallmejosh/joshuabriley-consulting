My Jobs Profile Documents
No rail, no panel — candidates get a
top-nav consumer shell on the same app.
  1. An internal operator can be looking at any client's data, so tenant identity belongs in the chrome rather than behind a settings page. The workspace name and the amber return-to-owner control stay visible for the whole session someone is impersonating — the mistake worth engineering against is acting on the wrong account and not noticing.
  2. ⌘K belongs to the shell but not to first paint. Its markup and its account-scoped search load on demand, so putting a global search surface on every page cost nothing on the hot path. It is additive rather than a replacement: per-page search stays, because the palette is for jumping across the app, not for filtering the screen you are on.
  3. The active state here is a semantic token, not a hex literal. A token system already existed in _color_tokens.scss — the failure was roughly forty views ignoring it. The shell's job was never to introduce tokens; it was to make the token path the shortest one, so a view has no reason to hand-roll a colour.
  4. Which section is open is decided server-side from the controller, so first paint is already correct and no client JS re-arranges the nav afterwards. This was Phase 2 of four, and it shipped without touching the ingestion pipeline underneath — that constraint is the reason this is a shell and not a rewrite.
  5. The sprawl was not caused by an absent system, so a style guide would not have fixed it. It was caused by every screen having somewhere of its own to decide. Navigation, page header, workspace context and search now come from one place — the counts are what the shell removes, not what it renames.
  6. Collapsed rail, read-only operator, candidate: one frame re-shaped by role and preference rather than three layouts maintained in parallel. Forked layouts drift within a quarter and the drift stays invisible until someone reports it. Density and rail state persist per user, so the choice survives a shift change.
