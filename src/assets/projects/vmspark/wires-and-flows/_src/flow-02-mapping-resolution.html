Entry Step System step Branch Commit Resolved Still failed Design note
  1. Unmatched rows sort first, so the list shrinks toward empty as the work is done. A queue that visibly empties is the difference between a chore with an end and a screen an operator stops opening — and the auto-map rules run before any of it, so a human only ever sees what the rules could not settle.
  2. Ignoring a value writes a record that it has no ATS counterpart, which is what stops it from re-queueing tomorrow. Without that, the queue never empties and the operator learns to distrust the count — a skip that silently returns is worse than no queue at all.
  3. The cursor lands on the next unmapped row rather than returning to the top of the list. Mapping debt is cleared in batches of forty, not one at a time, so the design optimises for the fortieth row rather than the first.
  4. A single facility mapping can touch thousands of listings, so nothing here happens in the request. The save returns instantly and the queue absorbs the fan-out — the alternative is an operator watching a spinner and deciding the tool is broken.
  5. A listing that still fails after a remap is information, not a bad fix. It points at a second missing mapping, so it stays in the queue rather than being marked resolved — the failure state has to survive the fix for the second problem to ever be found.
