4 of 24 unmapped facilities shown · load 20 more

  1. The queue is partitioned by entity type, because facilities, professions and specialties are settled by different people with different reference knowledge. Each tab carries its own unmapped count, and the same numbers sit in the sidebar badges — that badge is how anyone arrives here at all, from whichever screen they were on.
  2. Unmatched rows sort first by default, so the list visibly shrinks toward empty as the work is done. A queue with a visible end is the difference between a chore someone finishes and a screen they stop opening; sorting alphabetically would hide the end and cost nothing to fix later.
  3. Auto-map has already run before anyone sees this — exact match on name, street, city, state and zip — so what is left is only what the rules could not settle. The fuzzy candidates below that are ranked but never applied: a 92% guess is worth showing and not worth writing on the operator's behalf.
  4. Saving moves focus to the next unmapped row rather than returning to the top. Mapping debt is cleared in batches of forty, not one at a time, so this optimises for the fortieth row rather than the first — and the write itself is queued, because one facility mapping fans out to potentially thousands of listings and a synchronous save would leave someone watching a spinner.
  5. Ignore is a real decision, not a skip. It writes a record that this value has no ATS counterpart, which is what stops it re-queueing tomorrow morning. A skip that silently returns is worse than no queue at all — the count stops meaning anything and the operator learns to distrust it.
  6. A resolved row shows what the fix bought: nine listings unblocked, and which ATS roles the facility now fills. The cost of leaving a row alone is on the unresolved cards as blocked-listing counts, so triage order is a judgement about throughput rather than about which name looks easiest.
