  1. CSV import sits on the roster header beside “Add child”, not buried in settings. The empty board is the real churn risk, not the signup form — signup takes ninety seconds, entering twelve children by hand is the wall. A provider signing up already has the twelve written down from her licensing renewal.
  2. Lifecycle describes enrolment rather than today, and it changes rarely, so it belongs in tabs — a durable place she returns to, and a URL she can link or bookmark.
  3. Attendance is the second axis and gets its own date-scoped pill row. A child can be Active and Absent on the same morning; folding the two into one control would force her to reason about a state that does not exist.
  4. Enrolment status is derived, never toggled. There is no “Active” checkbox anywhere in the product — start and end dates decide it in a validation callback. She therefore cannot leave a child marked Active six months after they left, which is the commonest source of a wrong headcount, and a wrong headcount is a licensing problem rather than a display bug.
  5. Today's status is computed by reading the latest check-in, check-out or absent event for that child on that date. There is no attendance column in the database. It costs query complexity and buys correctness — voice, the kiosk, the board and the API all write events, and a stored flag drifts the moment one of the four forgets to update it.
  6. Archived children stay legible rather than vanishing. Attendance history feeds tax records and licensing audits, so removal is a display decision and not a data one — the record is soft-deleted and restorable.
