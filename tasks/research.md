Josh, measured against the $175K+ remote UX engineering and UI developer skill profile, your site is **well-positioned but under-evidenced**.

The positioning is strong. The homepage immediately says “UX Engineer & Design Systems Consultant,” leads with “I fix inconsistent UI systems so teams can ship faster,” and names the exact problem space these roles care about: inconsistent component libraries, duplicated components, accessibility debt, design/dev misalignment, tokens, documentation, and design-to-code workflow. That maps well to the premium-role pattern.

But the site currently reads more like a **consulting offer page** than a **senior/staff UX engineering proof page**. For freelance consulting, that may be fine. For $175K+ remote roles, it needs more hard evidence of technical depth, shipped systems, architecture, and outcomes.

The benchmark roles are not just asking for “good UI.” TeamSnap’s Staff Frontend Engineer role asks for React, advanced TypeScript, design systems, accessible components, design tokens, theming, E2E tests, CI/CD, performance, mentoring, and AI tooling. It starts at $200K total compensation. Veeva’s Principal Front-End role asks for architecture ownership, a custom UI framework, TypeScript, React, browser APIs, build tooling, testing strategy, and translating business goals into engineering outcomes, with a listed base range of $150K to $300K.

Your site clearly signals several of those skills, but it does not yet **prove** enough of them.

The biggest issue is this: **your site says you fix systems, but it does not yet show enough receipts.**

For a hiring manager, I’d want to see 2 or 3 case studies that answer these questions quickly:

What was broken? What did you change? What technical decisions did you make? What tradeoffs did you consider? How did you test it? How did you measure quality? What improved?

Right now, the site has strong positioning like “Components, tokens, and documentation done right” and “Design-to-code workflow,” which is good. But $175K+ roles need proof of execution at the level TeamSnap and Veeva describe: architecture, type-safe systems, testing strategy, performance, mentorship, and cross-team standards.

I’d make these changes first.

Add a **“Technical Proof” section** on the homepage. Keep it short. Something like:

“Where I’m strongest: design systems, accessible component architecture, semantic HTML/CSS, design tokens, Storybook documentation, frontend quality standards, and design-to-code workflows.”

Then add a second line that is honest but still strong:

“Current stack exposure includes Stencil Web Components, Storybook, Playwright, Gatsby documentation, Rails/ViewComponent, Vue/Nuxt, React/Next, and TypeScript.”

That immediately closes the gap between “consultant positioning” and “hireable senior UI engineer.”

Add 3 featured case studies under Projects. I’d use:

**Travelers Design System**
Focus: Stencil Web Components, React output, Storybook, Gatsby docs, Playwright, Jest, Figma Code Connect, Angular consumers, accessibility, documentation, multi-team adoption.

**Berkshire Hathaway Specialty Insurance UI System**
Focus: Vue/Nuxt, internal portals, design system, data-heavy UI, accessibility, performance, reusable patterns.

**America’s Test Kitchen UI Modernization**
Focus: React/Next, component library, Storybook, accessibility, performance, editorial/product collaboration.

Each case study should include a compact “skills proven” block. For example:

Skills proven: Design systems, accessibility, component APIs, documentation, frontend architecture, cross-functional collaboration, design-to-code alignment.

Then include a “technical details” block:

Stack: Stencil, TypeScript, Storybook, Playwright, Gatsby, Figma Code Connect.

That matters because recruiters scan for exact terms.

Add a **Staff-level evidence section**. You need to show leverage beyond implementation. Something like:

“I help teams make fewer repeated UI decisions by turning one-off fixes into reusable patterns, documented standards, and component-level accessibility rules.”

Then back it with examples:

“Created component usage guidance.”
“Reviewed UI implementation patterns.”
“Improved design/development alignment.”
“Reduced duplicated UI behavior.”
“Built accessible components with reusable interaction rules.”

The phrasing should be more concrete than inspirational.

Add a **Testing and quality section**. Right now, this is the most obvious missing proof. Premium roles are looking for automated tests, CI/CD, performance measurement, and quality systems. TeamSnap explicitly calls out unit, integration, E2E tests, CI/CD, observability, performance, and error rates.

You do not need to oversell. You could write:

“I use Storybook, Playwright, Jest, accessibility checks, semantic review, and manual keyboard/screen reader testing to catch UI defects before they become product debt.”

That one sentence helps a lot.

Add **React and TypeScript evidence**, even if your deepest experience is not React-only. This is important. The market is React/TypeScript-heavy. TeamSnap and Veeva both name React and TypeScript directly.

Your site should not pretend you are a pure React specialist if that is not the truth. But it should make your transferable experience obvious:

“Most of my work is framework-adjacent: component architecture, accessibility, interaction patterns, documentation, tokens, and front-end system quality. I’ve applied those skills across Vue/Nuxt, React/Next, Rails/ViewComponent, and Stencil Web Components.”

That is credible and plays to your actual strength.

My blunt recommendation: your current site is probably **excellent for design system consulting leads**, but only about **65% aligned** for $175K+ remote UX engineering or UI developer hiring. With stronger case studies and technical proof, it could get to **85%+** without a full redesign.

The highest-value fix is not visual. It is evidence. Add case studies, stack keywords, technical decisions, testing proof, and measurable outcomes. Your story is already good. Now the site needs to show that you can operate at the staff-level engineering bar, not just talk about broken UI systems.
